# Failure & Recovery Drill Matrix (`v1.0.0-rc.1`)

All 12 failure & recovery scenarios were executed across native binaries, Docker, Compose (SQLite & PostgreSQL 16), and RustFS S3, and recorded with observed outcomes.

| # | Scenario | Execution Environment & Method | Observed Result | Verdict |
|---|---|---|---|---|
| 1 | **Graceful `SIGTERM` during active work** | Native `prqnt serve` (`kill -TERM`), Docker (`docker stop -t 15`), Postgres Compose (`docker compose stop -t 15 parqonaut`), plus `events_and_idempotency::graceful_shutdown_drains_workers_and_flushes_events` | HTTP listener drained, active workers completed/flushed queued events, process exited cleanly with code `0` in all 3 runtimes | **PASS** |
| 2 | **Forced `SIGKILL` crash & restart recovery** | Docker `kill -s KILL` + restart, Postgres Compose `kill -s KILL` + restart, `fault_injection::lost_worker_heartbeat_recovers_or_exhausts_without_corrupt_commit`, `server_plugin_durable::recovery_runs_pinned_plugin_after_stale_lease` | Auth tokens, jobs, and runs survived intact; stale-lease `running` jobs atomically requeued with `job_recovered` event or exhausted cleanly without partial output | **PASS** |
| 3 | **Restart after unflushed progress events** | `bounded_memory::high_rate_event_burst_bounds_memory_and_retains_terminal`, `events_and_idempotency::graceful_shutdown_drains_workers_and_flushes_events` | Lossless `critical_tx` channel + `flush()` preserved lifecycle/terminal events; bounded retention (`<= 505` rows) preserved terminal `ExecutionCompleted` | **PASS** |
| 4 | **Database outage during operation** | Postgres Compose: stopped `postgres` while `parqonaut` remained running, then restarted `postgres` | During outage, `GET /api/v1/health/ready` returned `HTTP 500 {"error":{"code":"store_error","message":"internal storage error","details":{}}}` (no secret/URL leak). After `postgres` restart, `/health/ready` auto-recovered to `200 {"status":"ready"}` and `/api/v1/jobs` worked without restarting `parqonaut` | **PASS** |
| 5 | **Storage write failure during repair/transform** | `chaos_backend::local_permission_denied_atomic_write_leaves_no_output`, `chaos_backend::chaos_aborted_write_stream_leaves_target_absent`, plus live `prqnt repair` targeting an existing directory with `sentinel.txt` | `prqnt repair` exited `1` (`OutputExists`); `sentinel.txt` remained untouched and zero partial/staged artifacts leaked to target | **PASS** |
| 6 | **S3 multipart failure or interruption** | `chaos_backend::chaos_write_stream_multipart_part_failure`, `plugin_s3_cancellation::s3_plugin_pipeline_cancellation_aborts_upload`, `plugin_s3_cancellation::s3_mid_stream_plugin_failure_does_not_commit_partial_object` on live RustFS | Aborted multipart upload cleanly (`AbortMultipartUpload`); zero partial objects committed to `s3://parqonaut-test` | **PASS** |
| 7 | **Plugin subprocess crash / timeout / bad stdout** | `parqonaut-plugin-host` (`batch_crash_process_failed`, `batch_timeout_kills_child`, `descendant_processes_reaped_on_timeout`, `batch_stdout_contamination_protocol_violation`, `scan_adversarial`) + `plugin_runtime_gates::mid_stream_plugin_failure_leaves_no_committed_output` | Process-group descendants reaped, error mapped to `ScanFailed` / protocol violation with bounded stderr, and no partial output committed | **PASS** |
| 8 | **Cancellation of running job near completion** | `server_plugin_durable::cancel_slow_scan_plugin_job`, `plugin_runtime_gates::local_plugin_cancellation_during_pipeline`, `events_and_idempotency::repair_and_batch_jobs_emit_lifecycle_and_support_rbac_and_cancel`, `sqlite_store::concurrent_event_burst_and_cancel_no_sqlite_busy` | Cancellation recorded atomically (`BEGIN IMMEDIATE` in SQLite), plugin child reaped, terminal `job_cancelled` emitted without `SQLITE_BUSY` | **PASS** |
| 9 | **SSE disconnect & reconnect without duplicates** | Live SQLite & Postgres Compose (`?after_seq=2` replayed `[3, 4, 5]`) + `events_and_idempotency::scan_job_emits_ordered_events_and_sse_reconnects_without_duplicates` (`Last-Event-ID`) | Exact monotonic replay strictly after cursor, zero duplicate `seq` frames, terminal `job_status` delivered cleanly | **PASS** |
| 10 | **Concurrent duplicate submission (`Idempotency-Key`)** | Live Postgres Compose (identical replay returned same `job_id`, payload mismatch returned `409 conflict`) + `events_and_idempotency::concurrent_http_idempotent_submissions_create_single_job_and_canonical_json_matches` | Concurrent race persisted exactly one job row and returned consistent `202` response | **PASS** |

| 12 | **Permission / read-only / policy denial failure** | Docker `--read-only` rootfs, `StoragePolicy` HTTP `403 location_not_allowed`, `server_plugin_durable::storage_policy_rejects_before_plugin_spawn`, `chaos_backend::chaos_permission_denied_is_never_retry`, live `chmod 0555` parent dir `prqnt convert` | Denied before spawning plugins or retrying; `chmod 0555` `prqnt convert` exited `1` with zero partial output file | **PASS** |
